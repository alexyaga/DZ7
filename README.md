# AI Meeting Analyzer

Локальное приложение Light для Windows. Сервер принимает MP4 и WebM, распознаёт речь, составляет конспект в фоне и сохраняет историю встреч.

## Запуск двойным щелчком

После установки зависимостей и настройки `.env` откройте `Start.cmd` в папке проекта. Он запустит backend и frontend в фоне и откроет приложение в браузере. Повторный запуск использует уже работающие процессы. Если запуск не удался, проверьте `backend.log` и `frontend.log` в папке проекта.

## Установка и запуск в PowerShell

Установите Node.js 24 и pnpm 11.25.0. Из корня проекта выполните:

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
pnpm.cmd install --frozen-lockfile
```

Скачайте сборку [FFmpeg для Windows](https://ffmpeg.org/download.html#build-windows) с кодировщиком `libmp3lame`. Добавьте папку с `ffprobe.exe` и `ffmpeg.exe` в PATH или укажите полные пути в файле `.env`:

```dotenv
FFPROBE_PATH="C:/tools/ffmpeg/bin/ffprobe.exe"
FFMPEG_PATH="C:/tools/ffmpeg/bin/ffmpeg.exe"
```

Добавьте ключ проекта OpenAI в локальный `.env` в переменную `OPENAI_API_KEY`. Для транскрибации используется `OPENAI_TRANSCRIPTION_MODEL=gpt-4o-mini-transcribe` из ТЗ, для конспекта — `OPENAI_SUMMARY_MODEL=gpt-5-mini`. Обе модели используют один ключ. После изменения `.env` перезапустите backend. Vite публикует переменные с префиксом `VITE_`, поэтому ключ должен оставаться в серверной переменной.

В первом окне PowerShell запустите backend:

```powershell
pnpm.cmd dev:backend
```

Backend запускает Node.js с `--use-system-ca`, чтобы при подключении к OpenAI учитывались доверенные сертификаты Windows.

Во втором окне из той же папки запустите frontend:

```powershell
pnpm.cmd dev:frontend
```

Откройте http://localhost:5173 и проверьте статус «Сервер доступен». Выберите короткую MP4 или WebM с русской речью, которую можно отправить на распознавание. После проверки видео появится в истории со статусом «Обрабатывается». Сервер перекодирует первую аудиодорожку в монофонический MP3, 16 кГц и 64 кбит/с, отправит MP3 на распознавание, а текст — на создание конспекта. Выберите встречу, чтобы увидеть расшифровку, краткое содержание, решения, задачи и открытые вопросы.

Сервер проверяет конспект по строгой схеме. Если текст пустой, конспект пропускается. Расшифровка записывается на диск до формирования конспекта и доступна, если встреча получает статус «Ошибка». Запрос на конспект имеет таймаут 120 секунд и выполняется без автоматических повторов.

Обновите страницу или перезапустите backend, чтобы проверить историю. При запуске прерванные встречи получают статус «Ошибка» с сообщением о перезапуске и сохраняют уже полученную расшифровку. Один каталог `DATA_DIR` рассчитан на один процесс backend. История создаётся при первой принятой загрузке. В `data/meetings.json` содержатся локальные расшифровки и конспекты. При изменении `DATA_DIR` выбирайте каталог вне Git-репозитория, чтобы сохранить записи локальными.

Лимиты на одно видео — 30 минут и 750 МБ (750 000 000 байт). Лимит MP3 — 25 МБ (25 000 000 байт). Таймаут извлечения — 120 секунд, таймаут запроса к OpenAI — 180 секунд. OpenAI получает один запрос с серверной сегментацией по голосовой активности. SDK выполняет его без автоматических повторов. При пиковом уровне всей дорожки до −90 дБ включительно сервер возвращает пустую расшифровку без обращения к OpenAI. Параллельная загрузка получит `409`. Сервер удаляет временные файлы после обработки, ошибки или разрыва соединения. Для отдельной проверки API и сборки:

```powershell
Invoke-RestMethod http://localhost:3001/api/health
pnpm.cmd build
```

API должен вернуть `{"status":"ok"}`. Если остановить backend и обновить страницу, интерфейс покажет сообщение о недоступности. Оба сервера слушают localhost. При смене порта backend обновите `PORT` и `VITE_API_BASE_URL` в `.env`.

## Локальный импорт с Яндекс Диска

Вставьте публичную ссылку на один файл в раздел «Импорт с Яндекс Диска» и нажмите «Импортировать». В настройках ссылки должно быть разрешено скачивание. Backend скачивает видео во временный файл с таймаутом 5 минут. После проверки формата, размера, длительности и аудиодорожки он добавляет встречу в историю и запускает обычную обработку. Импорт и ручная загрузка используют один слот обработки.

Во время приёма файла интерфейс показывает скачивание или загрузку, затем проверку. В истории видны извлечение аудио, распознавание речи и подготовка конспекта. Повторный импорт или ручная загрузка совпадающего файла открывает уже обработанную встречу. Совпадение определяется по SHA‑256 содержимого, а если Яндекс Диск вернул совпадающие идентификатор и SHA‑256, повторное скачивание пропускается. Если предыдущая попытка оставила расшифровку, она используется из истории. Записи, сохранённые до добавления этой функции, загружаются как обычно. Для поиска дублей по ним нет хеша.

## Публичная демоверсия

Публичный интерфейс на Vercel собирается из того же репозитория с включённым режимом демонстрации. В проекте Vercel задайте публичный адрес туннеля в переменной `VITE_DEMO_API_URL` и выполните новый деплой. Без этой переменной на странице доступен готовый пример.

На Windows запустите отдельный API командой `pnpm.cmd dev:demo`. В локальном `.env` укажите точный адрес интерфейса Vercel как `DEMO_CLIENT_ORIGIN`. Свяжите Cloudflare Quick Tunnel с демо-API командой `cloudflared tunnel --url http://127.0.0.1:3002`. После запуска нового туннеля пересоберите интерфейс с новым `VITE_DEMO_API_URL` и обновите деплой в том же проекте. Для просмотра готового примера компьютер запускать не нужно.

Для публикации через Vercel CLI соберите интерфейс с `VITE_PUBLIC_DEMO=true` и `VITE_DEMO_API_URL`. В отдельной папке поместите содержимое `frontend/dist` в `.vercel/output/static` и создайте `.vercel/output/config.json` со значением `{"version":3}`. Из этой папки привяжите существующий проект через `vercel link` и выполните `vercel deploy --prebuilt --prod`. Так на Vercel попадут только файлы сборки.

Демо принимает публичную ссылку на видео до 5 минут и 100 МБ, выполняет одну задачу одновременно и принимает до 10 задач в сутки по UTC. В боковой панели видны встречи, запущенные в этой вкладке. Повтор той же ссылки открывает доступную встречу из этой истории без скачивания и нового обращения к OpenAI. Если предыдущая попытка завершилась ошибкой до получения расшифровки, ссылку можно отправить повторно. Выберите встречу, чтобы увидеть статус и результат или удалить её после обработки. Каждый результат хранится в памяти сервера до часа после завершения или до перезапуска сервера. Суточный счётчик хранится в `data/public-demo/quota.json`. API демоверсии работает на отдельном порту и обслуживает только маршруты `/api/demo/*`.

## Приёмка Light

Проверено на Windows 10 Pro (сборка 19045), Node.js 24.22.1, FFmpeg 9.0.2 и Edge.

| Проверка | Ожидаемый результат |
| --- | --- |
| Загрузить короткий MP4 или WebM с русской речью | Встреча появляется в списке. Статус меняется на «Готово», открываются расшифровка и четыре раздела конспекта |
| Загрузить файл без аудиодорожки, с подменённым расширением или длительностью больше 30 минут | Сервер объясняет причину отказа до создания встречи |
| Загрузить файл ровно в 750 000 000 байт, затем на один байт больше | Корректное видео на границе проходит проверку. Превышение возвращает `413` |
| Отправить второй файл, пока выполняется первая задача | API возвращает `409` |
| Обновить страницу и перезапустить backend после обработки | Встреча, расшифровка и конспект загружаются из истории |
| Прервать backend после записи расшифровки или получить ошибку при создании конспекта | Встреча получает статус «Ошибка», расшифровка остаётся доступной |
| Загрузить видео с цифровой тишиной | Встреча получает статус «Готово», интерфейс сообщает, что речь не распознана |

Полный цикл с реальным OpenAI проверен на синтетической русскоязычной записи WebM. Сценарии отказа проверены с отдельным каталогом данных и локальным имитатором OpenAI.

### Если запуск или обработка не удались

- Если порт занят, проверьте, запущен ли уже backend или frontend, и используйте имеющийся экземпляр.
- Если сервер сообщает, что FFmpeg или ffprobe недоступен, проверьте пути к обоим `.exe` в `.env` и перезапустите backend.
- Если длительность WebM не определяется, экспортируйте запись заново из приложения, которым она была создана, и повторите загрузку.
- Если OpenAI отклонил доступ или исчерпана квота, проверьте ключ, права проекта и доступ к обеим моделям в настройках OpenAI.
- Если backend сообщил об ошибке формата истории, сохраните копию `meetings.json` и восстановите корректный файл из резервной копии. Сервер останавливается до записи, чтобы повреждённая история осталась доступна для восстановления.

## Архитектура Light

- `frontend/` содержит React-интерфейс, загрузку, историю и опрос статуса.
- `backend/src/` содержит Express, обработчик встречи, репозиторий и отдельные модули проверки видео, извлечения аудио, транскрибации и конспекта.
- `data/tmp/` содержит временные видео и MP3. История хранится в `data/meetings.json`.

Приложение использует React, Vite с официальным React-плагином, Express и cors. Загрузка использует Multer, file-type для проверки контейнера, ffprobe для проверки потоков и длительности, FFmpeg для извлечения MP3 и официальный SDK OpenAI для транскрибации и конспекта. Схему конспекта проверяет Zod. Для атомарной записи истории используется write-file-atomic. Сравнение вариантов есть в [Исследование.md](Исследование.md).

| Маршрут | Контракт | Этап |
| --- | --- | --- |
| `GET /api/health` | `200` и объект со статусом `ok` | 1 |
| `POST /api/meetings/upload` | Один файл в поле `video` формы multipart. После проверки и записи в историю возвращает `202` и `{id}` | 2–6 |
| `POST /api/meetings/import/yandex-disk` | Принимает JSON со строкой `url`. Скачивает и проверяет файл и возвращает `202` и `{id}` | Pro |
| `GET /api/meetings/intake` | Возвращает текущий этап приёма файла в поле `stage` | Pro |
| `GET /api/meetings` | Список встреч с метаданными и статусами | 6 |
| `GET /api/meetings/:id` | Метаданные, расшифровка, конспект и ошибка выбранной встречи | 6 |
| `DELETE /api/meetings/:id` | Удаляет завершённую встречу или встречу с ошибкой вместе с данными. Возвращает `204`. Во время обработки возвращает `409` | Light |

При совпадении ручная загрузка и импорт возвращают `200` и `{id, duplicate: true}`.

Общий обработчик `processMeeting(meetingId, videoPath)` запускается в фоне с ограничением в одну активную задачу. Он извлекает аудио, сохраняет транскрипцию до вызова сервиса конспекта, удаляет временные файлы и записывает итоговый статус. Тот же обработчик сможет принять файл из будущего импорта в Pro.

Запись в истории содержит `id` (UUID), `filename`, `createdAt` (UTC), `source` (`manual`), `durationSeconds`, `status` (`processing`, `completed` или `error`), `transcript`, `summary` и `error`. Поля результата могут быть `null` до их заполнения. Репозиторий последовательно обновляет снимок и записывает его атомарно.

## Этапы и проверки

1. Каркас. Проверить доступность API из браузера, состояние при отключении сервера и сборку.
2. Загрузка. Проверить лимиты 30 минут и 750 МБ, фактический контейнер, длительность и наличие аудиопотока.
3. Извлечение аудио. Проверить MP3, пути с пробелами и кириллицей, таймаут и очистку временных файлов.
4. Транскрибация. Проверить реальные русскоязычные записи, тишину, лимит размера аудио и обработку ошибок API.
5. Конспект. Проверить схему JSON и смысл результата на записях с решениями, предложениями и неизвестными исполнителями.
6. История и фоновые задачи. Проверить конкурирующие загрузки, перезапуск и сохранение расшифровки при ошибке конспекта.
7. Приёмка Light на Windows 10 и уточнение инструкции по запуску.

Переход к каждому следующему этапу выполняется по отдельной команде. OpenAI планирует отключить `gpt-4o-mini-transcribe` 26 февраля 2027 года и рекомендует `gpt-transcribe` для готовых записей. [Документация OpenAI](https://developers.openai.com/api/docs/guides/speech-to-text)
